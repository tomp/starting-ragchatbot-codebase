● Codebase Overview

  This is a Course Materials RAG System - an educational Q&A application that
  uses Retrieval-Augmented Generation to answer questions about course content.

  Architecture

  Backend (FastAPI + Python 3.13)
  - app.py - Main API server with /api/query and /api/courses endpoints
  - rag_system.py - Orchestrates the RAG pipeline
  - vector_store.py - ChromaDB wrapper for semantic search
  - ai_generator.py - Anthropic Claude API integration with tool use
  - document_processor.py - Parses course files and creates chunks
  - search_tools.py - Tool definitions for Claude to search course content
  - session_manager.py - Manages conversation history per session

  Frontend (HTML/CSS/JavaScript)
  - index.html - Chat interface with sidebar
  - style.css - Dark theme styling
  - script.js - Client-side chat logic and API calls

  Sample Data
  - docs/ - Contains 4 course transcript files (course1-4_script.txt)

  How It Works

  1. Document Processing: Loads course files from docs/, extracts metadata
  (titles, instructors, lessons), and chunks content into ~800 character
  segments with overlap
  2. Vector Storage: Stores chunks in ChromaDB using Sentence Transformers
  embeddings (all-MiniLM-L6-v2 model)
  3. Query Processing: User asks questions via web UI → FastAPI endpoint → RAG
  system
  4. Tool-Based Search: Claude decides when to call the CourseSearchTool to
  retrieve relevant content
  5. Response Generation: Claude synthesizes answers from search results with
  source citations
  6. Session Management: Maintains conversation history (last 2 exchanges) per
  session

  Key Features

  - Semantic search across course content and lesson-specific filtering
  - Course name fuzzy matching via vector similarity
  - Claude tool use for controlled, fact-based responses
  - Session-based conversation context
  - Modern chat UI with suggested questions and course statistics
  - Markdown rendering for formatted responses

  Tech Stack

  - AI: Anthropic Claude Sonnet 4 (claude-sonnet-4-20250514)
  - Vector DB: ChromaDB 1.0.15
  - Embeddings: Sentence Transformers
  - Web Framework: FastAPI 0.116.1
  - Package Manager: uv

  Getting Started

  Run ./run.sh which starts the FastAPI server on port 8000. Requires
  ANTHROPIC_API_KEY in .env file.

● Course Materials Processing

  The course materials processing happens in document_processor.py through the
  DocumentProcessor class. Here's the detailed flow:

  1. File Reading (lines 13-21)

  - Reads files with UTF-8 encoding
  - Falls back to UTF-8 with error ignoring if normal read fails
  - Handles encoding issues gracefully

  2. Metadata Extraction (lines 110-146)

  The processor expects a specific format at the top of each course file:
  Course Title: [title]
  Course Link: [url]
  Course Instructor: [name]

  - Line 1: Extracts course title (or uses filename as fallback)
  - Lines 2-4: Checks first 4 lines for "Course Link:" and "Course Instructor:"
  patterns using regex
  - Creates a Course object with this metadata

  3. Lesson Parsing (lines 148-243)

  After metadata (starting from line 4), the processor looks for lesson markers:

  Pattern: Lesson N: Title (e.g., "Lesson 0: Introduction")

  For each lesson:
  - Extracts lesson number and title using regex: r'^Lesson\s+(\d+):\s*(.+)$'
  - Checks if next line contains "Lesson Link:" and captures it
  - Collects all content until the next lesson marker
  - Creates a Lesson object with metadata
  - Processes lesson content into chunks

  4. Intelligent Text Chunking (lines 25-91)

  This is the most sophisticated part:

  Step 1: Text Normalization
  - Normalizes whitespace (removes extra spaces/newlines)
  - Cleans up the text

  Step 2: Sentence Splitting
  - Uses smart regex: r'(?<!\w\.\w.)(?<![A-Z][a-z]\.)(?<=\.|\!|\?)\s+(?=[A-Z])'
  - Handles abbreviations correctly (e.g., "Mr." or "U.S." won't trigger splits)
  - Splits on periods, exclamation marks, or question marks followed by capital
  letters

  Step 3: Chunk Building
  - Configurable chunk size (default: 800 characters)
  - Builds chunks sentence by sentence
  - Adds sentences until chunk size would be exceeded
  - Maintains sentence integrity (never splits mid-sentence)

  Step 4: Overlap Calculation
  - Configurable overlap (default: 100 characters)
  - Counts backwards from end of chunk to find overlap sentences
  - Next chunk starts with overlap sentences from previous chunk
  - Ensures context continuity between chunks

  5. Context Enrichment (lines 184-189, 232-234)

  The processor adds contextual information to chunks:

  First chunk of each lesson (lines 184-188):
  "Lesson {N} content: {chunk_text}"

  Last lesson processing (lines 232-234):
  "Course {title} Lesson {N} content: {chunk_text}"

  This helps the vector search understand which lesson/course each chunk belongs
   to.

  6. Chunk Creation (lines 190-197)

  Each chunk becomes a CourseChunk object containing:
  - content - The text chunk (with context)
  - course_title - Parent course
  - lesson_number - Parent lesson
  - chunk_index - Sequential position in document

  7. Fallback Handling (lines 245-257)

  If no lesson markers are found:
  - Treats entire document (after metadata) as one course
  - Chunks the full content
  - Still creates CourseChunk objects with course_title

  Example Processing Flow

  Given a file like:
  Course Title: Introduction to RAG
  Course Link: https://example.com
  Course Instructor: Andrew Ng

  Lesson 0: What is RAG?
  RAG stands for Retrieval-Augmented Generation...

  Lesson 1: Vector Databases
  Vector databases store embeddings...

  The processor:
  1. Extracts: title="Introduction to RAG", link, instructor="Andrew Ng"
  2. Finds Lesson 0, collects its content
  3. Chunks Lesson 0 content into ~800 char pieces with 100 char overlap
  4. Adds "Lesson 0 content:" prefix to first chunk
  5. Repeats for Lesson 1
  6. Returns Course object + list of CourseChunk objects

  Key Configuration (from config.py)

  - CHUNK_SIZE = 800 - Maximum characters per chunk
  - CHUNK_OVERLAP = 100 - Character overlap between chunks

  This creates a rich, structured representation optimized for semantic search
  with proper context preservation.

  def _format_results(self, results: SearchResults) -> str:
      formatted = []
      sources = []

      for doc, meta in zip(results.documents, results.metadata):
          course_title = meta.get('course_title')
          lesson_num = meta.get('lesson_number')

          # Build context header
          header = f"[{course_title} - Lesson {lesson_num}]"
          sources.append(f"{course_title} - Lesson {lesson_num}")

          formatted.append(f"{header}\n{doc}")

      self.last_sources = sources  # Store for UI display

      return "\n\n".join(formatted)

● Course Materials Processing

  The course materials processing happens in document_processor.py through the
  DocumentProcessor class. Here's the detailed flow:

  1. File Reading (lines 13-21)

  - Reads files with UTF-8 encoding
  - Falls back to UTF-8 with error ignoring if normal read fails
  - Handles encoding issues gracefully

  2. Metadata Extraction (lines 110-146)

  The processor expects a specific format at the top of each course file:
  Course Title: [title]
  Course Link: [url]
  Course Instructor: [name]

  - Line 1: Extracts course title (or uses filename as fallback)
  - Lines 2-4: Checks first 4 lines for "Course Link:" and "Course Instructor:"
  patterns using regex
  - Creates a Course object with this metadata

  3. Lesson Parsing (lines 148-243)

  After metadata (starting from line 4), the processor looks for lesson markers:

  Pattern: Lesson N: Title (e.g., "Lesson 0: Introduction")

  For each lesson:
  - Extracts lesson number and title using regex: r'^Lesson\s+(\d+):\s*(.+)$'
  - Checks if next line contains "Lesson Link:" and captures it
  - Collects all content until the next lesson marker
  - Creates a Lesson object with metadata
  - Processes lesson content into chunks

  4. Intelligent Text Chunking (lines 25-91)

  This is the most sophisticated part:

  Step 1: Text Normalization
  - Normalizes whitespace (removes extra spaces/newlines)
  - Cleans up the text

  Step 2: Sentence Splitting
  - Uses smart regex: r'(?<!\w\.\w.)(?<![A-Z][a-z]\.)(?<=\.|\!|\?)\s+(?=[A-Z])'
  - Handles abbreviations correctly (e.g., "Mr." or "U.S." won't trigger splits)
  - Splits on periods, exclamation marks, or question marks followed by capital
  letters

  Step 3: Chunk Building
  - Configurable chunk size (default: 800 characters)
  - Builds chunks sentence by sentence
  - Adds sentences until chunk size would be exceeded
  - Maintains sentence integrity (never splits mid-sentence)

  Step 4: Overlap Calculation
  - Configurable overlap (default: 100 characters)
  - Counts backwards from end of chunk to find overlap sentences
  - Next chunk starts with overlap sentences from previous chunk
  - Ensures context continuity between chunks

  5. Context Enrichment (lines 184-189, 232-234)

  The processor adds contextual information to chunks:

  First chunk of each lesson (lines 184-188):
  "Lesson {N} content: {chunk_text}"

  Last lesson processing (lines 232-234):
  "Course {title} Lesson {N} content: {chunk_text}"

  This helps the vector search understand which lesson/course each chunk belongs
   to.

  6. Chunk Creation (lines 190-197)

  Each chunk becomes a CourseChunk object containing:
  - content - The text chunk (with context)
  - course_title - Parent course
  - lesson_number - Parent lesson
  - chunk_index - Sequential position in document

  7. Fallback Handling (lines 245-257)

  If no lesson markers are found:
  - Treats entire document (after metadata) as one course
  - Chunks the full content
  - Still creates CourseChunk objects with course_title

  Example Processing Flow

  Given a file like:

  Course Link: https://example.com

  Vector databases store embeddings...

  1. Extracts: title="Introduction to RAG", link, instructor="Andrew Ng"
  2. Finds Lesson 0, collects its content
  3. Chunks Lesson 0 content into ~800 char pieces with 100 char overlap
  4. Adds "Lesson 0 content:" prefix to first chunk
  5. Repeats for Lesson 1
  6. Returns Course object + list of CourseChunk objects

  Key Configuration (from config.py)

  - CHUNK_SIZE = 800 - Maximum characters per chunk
  - CHUNK_OVERLAP = 100 - Character overlap between chunks

  This creates a rich, structured representation optimized for semantic search
  with proper context preservation.

  def _format_results(self, results: SearchResults) -> str:
      formatted = []
      sources = []

          course_title = meta.get('course_title')
          lesson_num = meta.get('lesson_number')

          # Build context header

          sources.append(f"{course_title} - Lesson {lesson_num}")

          formatted.append(f"{header}\n{doc}")

      self.last_sources = sources  # Store for UI display

      return "\n\n".join(formatted)
